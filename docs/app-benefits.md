# AgentHub for Codexの概要とメリット

## 概要

AgentHub for Codexは、複数のCodexセッションをVS Codeのサイドバーからまとめて監視・操作するための拡張機能です。

セッションごとに別々のターミナルを開いて状況を確認する代わりに、実行状況、承認待ち、入力待ち、完了、失敗などを一つの一覧で把握できます。Codexとの通信には`codex app-server`を使用し、ターミナル画面の文字列解析には依存しません。

## 主なメリット

### 複数の作業状況を一か所で把握できる

複数のリポジトリや作業フォルダでCodexを動かしている場合でも、各セッションの状態と現在の作業内容を同じサイドバーで確認できます。ターミナルを順番に開いて進捗を探す手間を減らせます。

### 対応が必要なセッションを見つけやすい

実行中、承認待ち、入力待ち、完了、失敗、中断、切断といった状態を区別して表示します。利用者の判断が必要なセッションを見つけ、許可、拒否、回答などの操作へ移りやすくなります。

### 作業を中断せず追加の指示を送れる

実行中のセッションへ追加指示を送り、不要になった処理は中断できます。別の画面へ移動せず、一覧または詳細画面からセッションを操作できます。

### 実行内容と結果を確認しやすい

Codexのメッセージ、実行したコマンド、ファイル変更、ツール実行などのアクティビティを確認できます。一覧では最終結果を吹き出しで素早く確認し、詳細が必要な場合はセッション詳細画面を開けます。

### VS Codeの作業導線に統合できる

普段コードを編集するVS Code内でセッションの開始、監視、承認、追加指示、中断まで行えます。エディターとターミナルの間を頻繁に往復する必要がありません。

### セッションを再確認しやすい

Thread ID、タイトル、作業フォルダ、状態などのセッションメタデータを保存します。VS Codeを再起動した後も、保存されたセッションを一覧へ復元できます。

## 想定する利用場面

- 複数のリポジトリで調査、修正、テストを並行して進める
- 時間のかかるCodexの処理を任せながら別の作業を進める
- 承認待ちや入力待ちになったセッションだけをまとめて確認する
- 完了した作業の最終結果や実行履歴を後から確認する
- 誤った方向へ進んでいる処理を早めに中断し、追加指示を送る

## 技術面の特徴

- `codex app-server`のstdio JSONLプロトコルを使用
- PTYやターミナル画面の文字列解析に非依存
- セッション管理、Codex連携、VS Code表示の責務を分離
- 承認要求や入力要求をセッション状態として管理

## 現在の制約

現在は開発版です。主な制約は次のとおりです。

- VSIXパッケージによる通常配布は未対応
- Codex CLI以外のエージェントは未対応
- 自由入力型の`requestUserInput`と複数質問への一括回答は未完成
- app-serverプロセスの自動再起動は未対応
- 実環境でのVS Code E2Eテストは未整備

導入方法と詳しい操作は[利用マニュアル](./user-manual.md)を参照してください。
