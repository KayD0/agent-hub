# AgentHub for Codex 利用マニュアル

## 1. AgentHubでできること

AgentHub for Codexは、複数のCodexセッションをVS Codeのサイドバーでまとめて監視・操作する拡張機能です。

個別のターミナルを巡回せず、次の情報を確認できます。

- どのセッションが実行中か
- どのセッションが承認や入力を待っているか
- 完了、失敗、中断、切断したセッション
- Codexが現在行っている作業
- 実行したコマンド、ファイル変更、メッセージの履歴

Codexとの通信には`codex app-server`を使用します。通常のCodexターミナル画面を解析する方式ではありません。

## 2. 現在の提供形態

現在は開発版です。VS Codeへ通常インストールするVSIXパッケージはまだ作成していません。

このマニュアルでは、Extension Development Hostを使って動作確認する方法を説明します。

## 3. 必要な環境

- VS Code Desktop 1.100以降
- Node.js 20以降
- npm
- Codex CLI
- Codexの認証が完了していること

VS Code Web、`vscode.dev`、`github.dev`は対象外です。

### 3.1 バージョン確認

PowerShellで次を実行します。

```powershell
node --version
npm --version
codex --version
```

各コマンドのバージョンが表示されれば、実行ファイルを利用できます。

### 3.2 Codexの動作確認

通常のターミナルで一度Codexを起動し、認証と基本動作を確認してください。

```powershell
codex
```

AgentHubはCodexの認証情報を独自管理しません。Codex CLIが利用している認証状態を使用します。

## 4. 初回起動

### 4.1 プロジェクトを開く

VS Codeで次のフォルダを開きます。

```text
C:\00_hata\02_source\99999-agent-link\app
```

### 4.2 依存関係を導入する

VS Codeの統合ターミナルで次を実行します。

```powershell
npm install
```

### 4.3 コンパイルとテスト

```powershell
npm test
```

テストがすべて成功することを確認します。

### 4.4 拡張機能を起動する

1. VS Codeで`F5`を押します。
2. `Run AgentHub Extension`が実行されます。
3. 新しい「Extension Development Host」ウィンドウが開きます。
4. Activity BarからAgentHubアイコンを選択します。

起動前にTypeScriptのコンパイルが自動実行されます。

## 5. 新しいCodexセッションを開始する

### 5.1 開始操作

AgentHubサイドバー上部の`+`アイコンを選択します。

コマンドパレットから次を実行することもできます。

```text
AgentHub: 新しいCodexセッション
```

### 5.2 作業フォルダを選択する

次の候補が表示されます。

- 現在のワークスペースフォルダ
- マルチルートワークスペース内のフォルダ
- 最近使用したフォルダ
- `別のフォルダを参照...`

選択したフォルダが、そのCodexセッションの作業フォルダになります。

セッション開始後に作業フォルダを変更することはできません。別のフォルダで作業するときは、新しいセッションを開始してください。

### 5.3 ワークスペース外フォルダ

現在のVS Codeワークスペース外のフォルダを選択すると、確認ダイアログが表示されます。

パスを確認し、Codexにそのフォルダで作業させてよい場合だけ`このセッションで許可`を選択してください。

### 5.4 最初の指示を入力する

フォルダ選択後、Codexへの最初の指示を入力します。

例:

```text
このリポジトリのテスト失敗を調査して修正してください
```

入力した指示の先頭部分が、セッション一覧の表示名になります。

## 6. セッション一覧の見方

セッションは状態別に表示されます。

| グループ | 意味 |
|---|---|
| 要対応 | 承認または入力が必要 |
| 失敗・切断 | Codex処理の失敗、またはapp-serverとの切断 |
| 実行中 | セッション開始中、またはCodexが処理中 |
| 完了 | Codexのターンが正常完了 |
| 中断 | 利用者またはシステムがターンを中断 |

各セッション項目には次が表示されます。

- セッション名
- 作業フォルダ名
- 現在の状態
- 現在の作業内容（ツールチップ）

状態が変わると、セッションは対応するグループへ移動します。

## 7. 承認要求へ回答する

Codexがコマンド実行やファイル変更の承認を求めると、セッションが`要対応`へ移動します。

### 7.1 一覧から回答する

承認待ちのセッション項目には、インライン操作が表示されます。

- 許可
- 拒否

右クリックメニューから`このセッションで許可`を選択できる場合もあります。

### 7.2 詳細を確認して回答する

セッション項目を選択すると、詳細画面が開きます。

詳細画面には、可能な範囲で次が表示されます。

- 承認要求の種類
- 実行予定のコマンド
- Codexが提示した理由
- 許可、セッション内許可、拒否のボタン

表示内容を確認してから判断してください。

### 7.3 安全上の注意

- 内容が分からないコマンドは許可しないでください。
- 削除、上書き、外部送信、認証情報に関係する操作は特に注意してください。
- AgentHubが終了または切断した場合、承認要求が自動許可されることはありません。

## 8. Codexからの質問へ回答する

Codexが選択式の質問を送ると、セッションは`入力待ち`になります。

1. サイドバーで対象セッションを展開します。
2. 表示された選択肢を確認します。
3. 回答する項目を選択します。

現時点では、一覧からの回答は単一の選択式質問を主に想定しています。複数質問を同時に回答する操作や、Codexの入力要求に対する自由入力UIは未完成です。

通常の追加入力は、セッション詳細画面から送信できます。

## 9. セッション詳細画面

セッション一覧の項目を選択すると詳細画面が開きます。

詳細画面では次を確認できます。

- セッション状態
- 作業フォルダ
- 現在の作業
- Codexメッセージ
- コマンド実行
- ファイル変更
- ツール実行
- 承認とシステム操作の履歴

### 9.1 追加入力

画面上部の入力欄に指示を入力して`送信`を選択します。

追加入力は、実行中のターンへ`turn/steer`として送られます。

### 9.2 中断

`中断`を選択すると、現在実行中のターンへ中断要求を送ります。

すでに完了している場合や実行中のTurn IDがない場合は、エラーメッセージが表示されます。

## 10. 通知

既定では次の場合にVS Code通知が表示されます。

- 承認待ち
- 入力待ち
- 完了
- 失敗または切断

通常の進捗更新では通知されません。

## 11. 設定

VS Code設定で`AgentHub`を検索してください。

| 設定 | 既定値 | 説明 |
|---|---:|---|
| `agentHub.codexPath` | `codex` | Codex CLI実行ファイルのパス |
| `agentHub.notifyOnActionRequired` | `true` | 承認・入力待ちの通知 |
| `agentHub.notifyOnComplete` | `true` | 完了通知 |
| `agentHub.notifyOnFailure` | `true` | 失敗・切断通知 |

### 11.1 Codexが見つからない場合

PATHから`codex`を起動できない場合は、`agentHub.codexPath`へ実行ファイルの絶対パスを設定します。

Windowsでnpmのグローバルインストールを利用している場合、環境によっては`codex.cmd`のパスを指定する必要があります。

設定変更後は、Extension Development Hostを再読み込みしてください。

## 12. セッションの復元

AgentHubはセッションのThread ID、タイトル、作業フォルダ、最終状態などをVS CodeのglobalStateへ保存します。

VS Codeの再起動後は、保存されたThreadをapp-serverへ再接続します。

注意事項:

- 保存された承認待ち状態をそのまま信用して再表示することはありません。
- 復元できなかったセッションは`切断`として表示されます。
- 復元後のセッションは、現在の実装では`再開可能です`として完了グループへ表示されます。

## 13. 一覧からセッションを削除する

完了、失敗、中断、切断状態のセッションを右クリックし、次を選択します。

```text
AgentHub: 一覧から削除
```

この操作はAgentHubの一覧と保存メタデータから除外します。現時点ではCodex側のThreadを削除またはアーカイブしません。

## 14. ログを確認する

次の操作でAgentHubのOutput Channelを表示します。

1. `表示` → `出力`を開きます。
2. 出力チャンネルから`AgentHub`を選択します。

ここにはapp-serverのstderrや接続エラーが表示されます。

## 15. トラブルシューティング

### 15.1 AgentHubアイコンが表示されない

- 通常のVS Codeウィンドウではなく、Extension Development Hostを確認してください。
- `npm run compile`が成功するか確認してください。
- `開発者: ウィンドウの再読み込み`を実行してください。

### 15.2 app-serverを起動できない

- 統合ターミナルで`codex --version`が成功するか確認してください。
- `agentHub.codexPath`を確認してください。
- AgentHub Output Channelでエラー内容を確認してください。

### 15.3 セッション開始直後に失敗する

- Codexの認証が完了しているか確認してください。
- 選択した作業フォルダが存在するか確認してください。
- 通常のCodex CLIで同じフォルダを使用できるか確認してください。

### 15.4 セッションが切断になる

- app-serverプロセスが終了した可能性があります。
- AgentHub Output Channelを確認してください。
- Extension Development Hostを再読み込みしてください。

切断中の承認要求は安全のため破棄され、自動許可されません。

### 15.5 選択肢が表示されない

- 対象セッション項目の左側にある展開アイコンを選択してください。
- 自由入力だけを求める質問は、現在のMVPでは一覧に回答UIが表示されません。

## 16. 現在の制約

- 開発版であり、VSIX配布は未対応
- Codex CLI以外のエージェントには未対応
- 通常のCodex TUIやターミナル表示は提供しない
- PTY、remote TUI、app-server WebSocketは使用しない
- app-serverプロセスの自動再起動は未対応
- 自由入力型の`requestUserInput`は未完成
- 複数質問への一括回答は未完成
- 完了済みThreadのCodex側アーカイブ・削除は未対応
- セッション詳細のアクティビティは実行中メモリに保持され、再起動後には復元されない
- 実環境でのVS Code E2Eテストは未実施
